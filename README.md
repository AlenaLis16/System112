# Учебный тренажёр подготовки диспетчеров ДДС города Москвы

Проект реализован как локальный веб-сервис на Django с PostgreSQL и локальной моделью Qwen через Ollama.

## Назначение

Основной учебный контур MVP ориентирован на диспетчера ДДС. Карточка уже сформирована системой 112 и поступает в конкретную ДДС. Диспетчер не редактирует исходные поля карточки. Он устанавливает статусы, делает служебные комментарии, фиксирует замечания по исходным данным и взаимодействует с руководителями реагирующих служб через программную модель IP-телефона.

Цикл обработки карточки:

1. Принято
2. Не принято
3. Начало реагирования
4. Прибытие
5. Проведение работ
6. Завершение
7. Отказ

Для отказа требуется мотивированная причина.

Нормативы MVP:

- 30 секунд — открытие поступившей карточки;
- 3 минуты — до первой записи, статуса или комментария;
- последующая работа по карточке может продолжаться длительное время.

## ИИ

Qwen подключается через Ollama. Адрес модели задаётся переменными окружения `OLLAMA_URL` и `OLLAMA_MODEL`, поэтому решение не привязано к внешнему API.

Модель используется для:

- формирования учебных карточек;
- формирования служебного ответа руководителя реагирующей службы;
- первичного анализа результата.

Поправки преподавателя сохраняются отдельно и передаются в последующие запросы формирования учебных карточек. Это обеспечивает механизм накопления учебных поправок без заявления о фактическом дообучении весов модели.

## Запуск

```powershell
py -3.11 -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для PostgreSQL:

```powershell
docker compose up -d
```

Создать `.env` по образцу `.env.example`.

```powershell
venv\Scripts\python.exe manage.py migrate
venv\Scripts\python.exe manage.py seed_demo
venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000
```

## Демонстрационные учётные записи

Преподаватель:

`teacher / Teacher112!`

Диспетчер ДДС:

`trainee / Trainee112!`

Административный контур доступен через стандартную Django Admin.

## Классификатор

Файл `data/classifier.xlsx` является учебным источником данных, предоставленным для проекта. В MVP используются учебные коды и типы происшествий. Версия классификатора считается уточняемой заказчиком.

## Телефония

Физический IP-телефон не требуется. На АРМ реализована программная модель внутреннего IP-телефона. Фокус MVP — связь диспетчера ДДС с руководителем реагирующей службы. Диалог с заявителем в основной учебный путь не включён.

## Важное решение по голосу

Для MVP не требуется делать голосового ИИ-заявителя и записывать речь диспетчера. Это не является основным пользовательским путём после уточнений заказчика. Для демонстрации реализован более релевантный канал: исходящий служебный звонок диспетчера ДДС руководителю реагирующей службы с текстовым протоколом и озвучиванием ответа браузером.
